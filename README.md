# Wust El Balad

A standalone multiplayer pixel-art society set in downtown Cairo. Ten autonomous citizens live their own lives while up to six observers investigate. Currency: **EGP**. Newspaper: **The Downtown Gazette**.

## Run

Requires Node.js 22 or newer and npm. From the repository root:

```sh
npm install
```

Copy `.env.example` to `.env` (Windows: `copy .env.example .env`; Linux/macOS: `cp .env.example .env`). Credentials can remain empty for Task 01.

```sh
npm run build
npm start
```

Open http://localhost:3000. Express serves the frontend and `/api/health` on the same port. `PORT` changes the production port; `HOST` defaults to `0.0.0.0`.

Development: `npm run dev` (frontend http://localhost:5173, API port 3000 or `PORT`).

Checks: `npm run typecheck`, `npm run lint`, `npm test`.

## Progress and rules

- Task 01: runnable React/Vite/Tailwind + Express/TypeScript foundation, shared health contract, environment template, and CI.
- Task 02: versioned SQLite migrations and ten seeded Cairo citizens, buildings, directed relationships, and private initial knowledge. `GET /api/world/summary` returns a safe public summary.
- `DATABASE_URL` defaults to `file:./data/world.db`. Startup creates the database once and reopens it without reseeding. Amounts in storage are integer piastres (100 piastres = 1 EGP). Keep the `data` directory on durable storage; do not copy an active WAL database for backups.
- Task 03: signup/login/logout, persistent hashed sessions, username/avatar updates, and admin authorization. Usernames: 3–24 ASCII letters, digits, or underscores; passwords: 10–128 characters. Six non-banned observer accounts can register; the separate administrator does not occupy a player slot. Avatar artwork arrives in Task 06.
- Accounts use server-side sessions, so `JWT_SECRET` is reserved and unused. Set `SESSION_COOKIE_SECURE=true` behind production HTTPS. For one-time admin creation, set `ADMIN_SECRET` to at least 32 characters and POST `{username,password,confirmPassword}` to `/api/auth/admin/bootstrap` with the secret in `x-admin-secret`. Use HTTPS remotely; never embed this secret in frontend code. Existing admins log in normally. `/api/auth/admin/status` requires an authenticated admin.
- Task 04: durable clock/ticks, atomic idempotent world commands, once-only day boundaries, and single-writer protection. `DAY_DURATION_HOURS=6` means one game day per six real hours; `SIMULATION_TICK_MS=1000` controls committed tick frequency. `/api/world/summary` reports the current day, minute, tick, and version.
- The clock uses elapsed time while the process runs, not wall-clock catch-up. Zero observers do not stop it. Clean shutdown releases the writer lease; after a crash, a second process may need to wait for the stale lease (15 seconds with default settings). Run only one simulation instance per database. A storage failure stops the process rather than continuing unpersisted state.
- Task 05: four-direction pathfinding, non-overlapping movement, saved paths/work schedules, hunger/energy/social needs, and utility-based work/eat/sleep/social decisions. Routine activity and contextual dialogue work with no AI key. Buildings are logical entrance zones at this stage; the pixel map/UI arrives in Tasks 06–08, economy in Task 09.
- After signing in, open `/api/world/citizens` to inspect the authenticated read-only positions, activities, and building zones. It exposes no private thoughts, memories, secrets, or credentials. Each tick saves movement, needs, routine state, and generated activity records in one transaction.
- Task 06: self-contained pixel matrices generate terrain/trees/flowers/lamps, seven distinct building types, ten portraits, four-direction three-frame walking sprites, and HUD/job/emote icons. Click **Preview pixel art** to see the animated atlas. Profiles show the selected generated observer portrait. No sprite downloads or external images are needed.
- Task 07: authenticated Socket.IO snapshots and committed/versioned deltas share the same world with all observers. Login to see the live day/time, unique connected-player count, tick, and movement readout. Reconnects receive fresh snapshots; gaps trigger resynchronization, duplicate/old deltas are ignored, and revoked/banned sessions are disconnected. Socket clients cannot pause or set world state.
- Task 08: click **Enter town** after login for the map-led pixel-RPG HUD. Drag/touch-pan, pinch or use +/- to zoom, tap a citizen to inspect, and use **Follow on map**. Desktop uses side panels; mobile uses bottom navigation and slide-up sheets. Day/night lighting follows the server clock. Pixel fonts are bundled locally. Tools link to the planned gameplay views and explicitly label panels awaiting their later tasks.
- Task 09: attendance-based wages, daily rent, paid meals/stock, employment changes, segregated savings, loans/repayments, and overdue/shortfall consequences run in the authoritative transaction. Amounts are integer piastres. Fictional defaults: meals EGP 25, daily rent EGP 20, full-shift wages EGP 80–120; businesses and bank lending begin with finite capital. Loan limits, opening hours, funded vacancies, balances, and retries are validated. Players cannot directly move NPC money or change jobs.
- After login, `GET /api/economy/karim` (or another citizen ID) shows the public economic statement/transaction ledger; the character sheet shows live cash, savings, and debt. Unaffordable food does not restore hunger, and restarting does not pay wages or charge rent twice.
- Task 10: witnessed events and received dialogue update directed trust, affection, respect, fear, debt, grudge, suspicion, dependence, reputation, mood, goals, and uncertain beliefs. Routine witnesses are captured when events occur. Hidden actions do not automatically tell their victim who performed them, and financial records are known only to their participants/owners.
- The five memory layers have strict storage caps (24 short-term, 32 episodic, 24 relationship, 32 belief, 16 long-term) and source-event provenance; knowledge is capped at 48 entries. AI retrieval uses at most 20 memories, 6 beliefs, 6 own conversations, 6 relationships, 5 authorized secrets, and 8 debts with a separate debt total. Compaction never removes canonical dialogue history or turns hearsay into confirmed facts. Secret sharing requires an actual holder and records uncertain, private provenance.
- The character sheet's social panel and authenticated `GET /api/social/karim` show all outgoing relationship dimensions and disclosed memories. Private goals, private knowledge, secret identifiers, and the internal AI context are not exposed. No external AI service is needed for these updates.
- Task 11: official Gemini, NVIDIA NIM, OpenRouter, Groq, native Ollama, and custom OpenAI-compatible transports feed a bounded queue with request/token budgets, timeouts, at most two attempts per provider, per-key errors, origin-wide 429 backoff, ordered fallbacks, and a validated local policy. Missing keys or failed providers do not stop the clock. Idle citizen requests are throttled; opt-in batching never mixes different citizens' private contexts. Runtime settings are implemented in Task 12; citizen reasoning uses this infrastructure in Task 13.
- Set `GEMINI_API_KEY` and `GEMINI_MODEL`, or configure `AI_PROVIDERS_JSON` with provider `id`, `kind`, `model`, `enabled`, `priority`, and `keys` containing `id`, `value`, and `enabled`. The transports supply vendor base URLs; `baseUrl` and model-dependent `jsonMode` (`schema`, `object`, `prompt`) can be specified. Compatible environment mode uses `OPENAI_COMPATIBLE_BASE_URL`, `AI_PROVIDER_MODEL`, and `AI_PROVIDER_KEY`, not a sandbox AI key. Never commit populated credentials. Additional private/local service origins must be explicitly listed in `AI_ALLOWED_ORIGINS`; default local Ollama port 11434 is permitted. DNS validation/pinning, body limits, and rejected redirects protect outbound requests.
- Authenticated administrators can GET `/api/admin/ai/status` and POST `/api/admin/ai/test`. The test reports `network` versus `local` rather than falsely treating fallback as a successful provider connection. Gemini quota is project-wide; rotation does not increase it. Protocol references: [Gemini](https://ai.google.dev/api/generate-content), [NIM](https://docs.api.nvidia.com/nim/reference/llm-apis), [OpenRouter](https://openrouter.ai/docs/api-reference/overview), [Groq](https://console.groq.com/docs/api-reference#chat-create), [Ollama](https://docs.ollama.com/api/chat).
- Task 12: administrators can open Tools → AI Settings to manage providers, models, URLs, priority/fallback order, the preferred active provider, multiple write-only keys, and explicit connection tests without a rebuild or world reset. Settings and safe audit records persist in SQLite; environment providers are imported only on first initialization. Per-key errors and shared-origin quota cooldowns survive restarts. Changing the service type/origin disables existing keys until explicitly re-enabled. In-flight requests may finish, but old credential failures cannot disable newly replaced keys.
- API keys are AES-256-GCM encrypted and never returned by settings, status, tests, or audit APIs. Set `AI_ENCRYPTION_KEY` to a base64-encoded 32-byte key, or let the server create a mode-0600 `.ai-encryption-key` beside the database when the first key is stored. Back up that private file or your configured master key separately with the database; losing it makes stored provider keys unavailable, not the town itself. The file is ignored by Git and never served.
- Task 13: citizen reasoning asynchronously uses only that citizen's memories, received claims, private knowledge, subjective relationships, and nearby public observations. Significant experiences/needs and persisted cadence trigger decisions without blocking ticks. Both network proposals and enriched local utility policies use the same typed action/resource validator for waiting, path-based destinations, attributed speech, and transfers. Current balances, proximity, source references, response age, and writer transactions are rechecked; proposals cannot teleport, double-spend, or rewrite committed facts. Missing providers still produce local dialogue and decisions.
- AI-to-AI dialogue is recorded with participants, time, source event, and private provenance for each participant's Character Chat. Beliefs or lies remain attributed utterances, not confirmed facts; private lie intent is not exposed through public events. Interrogation uses only that citizen's observations, received information, or beliefs.
- Task 14: Tools → Character Chat shows read-only chronological dialogue for the selected citizen, including each conversation in both participants' histories, grouped by game day. Observer Chat is a separate human-only stream and never becomes NPC memory automatically. Both offer bounded cursor pages and reconnect-safe live update signals; observer writes are transactional, rate-limited, and retry-idempotent. Events shows only public events of importance 50 or higher, while routine activity stays in the map ticker. The map displays the newest short speech bubble per speaker and lightweight public-mood emotes. Authenticated stream endpoints: `GET/POST /api/chats/observer`, `GET /api/chats/characters/:id`, and `GET /api/events` (`before`/`after` cursors, up to 100 rows).
- Task 15: Tools → Interrogation (or Interrogate in a character sheet) asks any citizen about their own observations, received claims, beliefs, and personal circumstances. The RPG portrait follows public mood. AI may select relevant authorized evidence, uncertainty, or refusal, but answer text is rendered from that citizen's source claims rather than unconstrained model prose. Heard claims and beliefs are explicitly labeled; different citizens may give contradictory accounts. No-key mode supports basic questions and honestly reports missing knowledge. Questions are inquiries only: they do not inject memories, change goals, spend influence, or trigger actions. Only the requester can read their stored interrogation history. Questions are limited to 1,000 characters and 20 per real minute per player; there is no invented daily questioning allowance. Endpoints: `GET /api/interrogations?citizenId=…` and `POST /api/interrogations/:citizenId` with `question` and optional retry `commandId`.
- Task 16: A game-day boundary freezes a public-only source snapshot, then the chronicler publishes one stable edition of **The Downtown Gazette**. Configured AI can curate actual source IDs; no-key mode creates a deterministic edition. Published editions are never regenerated after provider recovery. Confirmed records, rumors, and unverified accounts are visibly distinct; reporting may omit events and quoted claims can be mistaken, but cannot rewrite facts or expose private ledger details. Tools → Town Archives / The Downtown Gazette provides day selection, bounded older timeline pages, timestamps, and links to public causal predecessors. Existing closed days are backfilled from the ledger on startup. APIs: `GET /api/archives` (up to 60 days, optional `beforeDay`), `GET /api/archives/:day`, and `GET /api/archives/timeline/:day` (`before`/`anchor`, up to 100 records). A pending edition remains explicitly pending until finalized.
- Rumors require all registered, non-banned players to approve, with a 24-real-hour timeout.
- Simulation time does not advance while the server is off.

No Manus SDK, proxy, external authentication service, or managed database is required. Do not commit credentials, world databases, or backups.
- Task 17: Tools → Investigation accepts one immutable report per closed game day, or an explicit zero-reward skip. Other players' finalized answers remain hidden until you submit or skip that day. Server-private structured action facts freeze at the same day boundary; rumors and spoken assertions are not objective facts. Configured AI evaluates evidence spans in one bounded batch, with deterministic entity/action-synonym/counterparty/location/EGP-amount checks and a no-key fallback. Scores are audited and awards are atomic, retry-safe, and capped at 12 Influence Points per day; unsupported claims earn nothing. No streak mechanic. APIs: `GET /api/investigations`, `GET/POST /api/investigations/:day`, and `POST /api/investigations/:day/skip`. Ground-truth records and private evidence IDs are never returned in these APIs.
- Task 18: Influence opens your live wallet and a daily citizen-suggestion opportunity. Costs default to subtle 2, medium 5, strong 9 and are configurable in `.env.example`; validated opportunities spend points and the daily allowance even when considered, ignored, or rejected. Accepted nudges are not guaranteed story outcomes: they become attributed, uncertain memories and at most a bounded, expiring bias toward already-legal utility choices. Urgent needs and resource rules take priority; no direct money, relationship, movement, or truth edits. Identical retries never spend twice. Public generic suggestion events support later causal links without exposing private suggestion text. API: `GET /api/influence`, `POST /api/influence/interventions`.
- Task 19: Tools → Rumors provides a synchronized, collaboratively editable proposal and explicit exact-revision approval board. Every registered non-banned account, including administrators who observe the world, must approve; edits invalidate approvals and published text/voters are immutable. One global proposal opportunity per three simulated days; pending proposals expire after 24 real hours, including server downtime, without advancing game time. Safe fictional-world claims may be false: publication and local citizen spreading create attributed, uncertain rumor beliefs, never historical theft/guilt facts. Only awake, knowledge-authorized citizens spread through legal nearby conversations, and confidence decays or weakens when their own observations contradict a supported claim. APIs: `GET/POST /api/rumors`, `PATCH /api/rumors/:id`, `POST /api/rumors/:id/approve`.
- Task 20: Tools → Catch up preserves the previous visit before recording current presence, lists closed missed/unreviewed days with quick headline/count summaries, and opens their actual newspaper, timeline, character conversation history, or still-eligible investigation. Reviewed days and zero-reward skips persist; reconnecting never hides unreviewed days. Being offline itself never deducts Influence or adds a streak penalty. `GET /api/catch-up`, `POST /api/catch-up/:day/review`, `POST /api/catch-up/:day/skip`; character history accepts an optional game-day filter.
- Task 21: Tools → Leaderboard ranks durable, non-banned player/observer records by current Influence, weighted investigation accuracy, discoveries, then stable ID. Profiles show completed investigations, weighted accuracy, major events discovered, accepted-suggestion interventions, and exact-final-version approved published rumors; pending/skipped investigations and unapproved/expired rumor versions never inflate these metrics. Intervention success means accepted for consideration, not a guaranteed downstream action. Public profiles expose no investigation answers, hidden fact IDs, passwords, or private context; your own profile retains username and locally generated pixel-avatar selection. No streak metric or penalty. APIs: `GET /api/leaderboard`, `GET /api/players/:id`.

## Milestone 5 operations

- Task 22: Admin-only `GET /api/admin/world/export` creates a consistent online SQLite backup (including committed WAL data) and downloads it as `wust-el-balad-world.sqlite`. To restore, upload a backup with `POST /api/admin/world/restore`, content type `application/vnd.sqlite3`, and an authenticated admin session. The server validates SQLite integrity and world presence, rejects schema versions newer than the running app, then stages the file without touching the live database. Supported older versions migrate forward on startup. Restart the service to activate the restore; the previous database is retained as `<database>.pre-restore-<timestamp>`. Restore uploads are limited to 256 MiB. Back up `.ai-encryption-key` separately if provider credentials are stored; database backups do not contain that file.
- Task 23: `docker compose up --build -d` builds and starts the single-port app. Set secrets in `.env` (never bake them into the image); Compose persists SQLite and the encryption key under `./data`. Keep that directory on a durable volume on any host, expose port 3000 through the host's HTTPS proxy, set `SESSION_COOKIE_SECURE=true`, and configure `JWT_SECRET` (reserved) and a strong `ADMIN_SECRET`. For a VM/VPS, install Docker Engine and the Compose plugin, clone/export the repository, create `.env`, then run the same Compose command. On managed container hosts, build from this Dockerfile, set the same environment variables, attach a persistent disk at `/app/data`, and route the public port to container port 3000. Do not run multiple replicas against one SQLite database.
- Task 24: Release verification is run with `npm run typecheck`, `npm run lint`, `npm run build`, and `npm test`; CI runs all four plus a Docker image build on pushes and pull requests. The test suite covers persistence/restart recovery, single-writer coordination, command idempotency, provider failures, auth boundaries, and gameplay flows. Before deploying a release, also verify the Docker image starts with a mounted data directory and exercise backup/restore against a disposable database.
